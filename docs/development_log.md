# Development decisions and evidence
This log preserves the what/how/why for the user's later complete software-process explanation. It is not a claim that later milestones are complete.

## Milestone 1 — foundation
The PRD separated the presentation layer from reusable processing to support independent testing and a future native interface. The implementation used a src package, Pydantic contracts, standard CSV/JSON parsing, safe local YAML, and Streamlit session-only state. Unknown metadata, original IDs, whitespace and token spellings were retained for traceability. Malformed files fail atomically; invalid domain rows produce safe diagnostics. Input limits and localhost settings bound the local prototype without adding cloud/auth/database scope.

Evidence: 36 tests passed at completion, plus Ruff, mypy, pip-audit and a localhost health check. Bootstrap pip vulnerabilities were fixed rather than suppressed. The source PRD and GitHub reference were preserved. See milestone_1_completion.md for the recorded results.

## Milestone 2 — deterministic analysis
Pure functions were chosen before AI so rules could produce reproducible, explainable results. Literal phrase matching avoids executable configuration regex; protected spans prevent terminology rules from altering technical tokens/product names. Findings remain separate from source text. Stable IDs identify equivalent rule evidence, while a full input fingerprint prevents stale UI results. A multiset token comparison catches duplicated occurrences as well as missing/renamed tokens. Conservative same-screen/component grouping avoids claiming semantic equivalence across unrelated contexts.

Evidence: 73 tests passed at completion, including source/config immutability, token-prefix and custom-token whitespace regressions, exact human-authored FleetOps expectations, and UI filters/staleness. No AI or approval workflow was introduced. See milestone_2_completion.md.

## Milestone 3 — local contextual suggestions
Ollama is optional and confined to a dedicated adapter. Standard-library HTTP avoided adding an SDK dependency and made proxy/redirect behavior explicit. Numeric loopback endpoints and local-weight metadata checks enforce the intended local-service boundary; the local daemon remains trusted. Fixed endpoints omit model pulls and tools. Strict model-output contracts forbid extra model-controlled fields such as approval status. Per-record outcomes preserve useful results when another record fails.

The model's instructions and serialized source data are separate. Byte/record/token/time bounds prevent unbounded requests. Temperature and seed are fixed for more repeatable runs, without promising determinism. The app assigns identifiers, source links and pending review state; model text cannot become instructions, commands, HTML or automatic product changes.

Grounding uses explicit product_behavior evidence rather than generic context. Missing evidence becomes clarification. Exact evidence quotes, token integrity, fit, protected names, terminology and conservative vocabulary/negation/number checks gate candidates. This choice deliberately favors withholding a plausible paraphrase over inventing product behavior. It does not prove semantic entailment, so every remaining candidate still requires human behavior confirmation. A dedicated fictional AI sample provides usable evidence without falsely treating the generic 40-string catalog as verified specifications.

Verification combines mocked offline responses with a separately reported live smoke test. Tests cover success, malformed/foreign output, prompt isolation, missing evidence, protected-token changes, partial runs, unavailable models, proxy/redirect boundaries, bounds and UI behavior. The first live call reached its 60-second limit; Ollama reported CPU-only inference. The configuration was tuned to a bounded 120-second timeout and 512-token output budget. Final outcomes are recorded in milestone_3_completion.md.

Previews, human approval controls, exports and persistent storage remain outside this milestone. Decisions and measured results here will support the later full process explanation when requested.

The local smoke retry completed in 50.91 seconds with evidence-backed pending candidates for the fictional report button. A separate missing-behavior error test completed in 70.97 seconds with clarification questions and zero revisions. The model repeated an identical candidate under several findings; the application now coalesces identical candidate text per source without dropping findings. Final release checks passed 143 tests, Ruff, strict mypy and pip-audit; the localhost app was refreshed to 0.3.0.

## Milestone 4 — inspect before acceptance
The PRD calls for five fixed component previews, independent of the audit engine. A pure snapshot model keeps exact original/revised copy and computes code-point usage plus advisory layout budgets; the renderer stays in a separate ui package. This supports future native rendering without Streamlit in the engine. Explicit estimates avoid claiming measured browser/font fit. Overlength copy remains inspectable, while token-invalid or foreign-source revised copy is withheld.

Text is escaped before insertion into fixed scoped HTML and displayed through sanitized st.html with JavaScript disabled. No source value enters a style, attribute, URL or executable context. A raw iframe HTML API was avoided because it permits unnecessary script/origin capabilities and is deprecated in the installed Streamlit version. Static disabled controls and native helper disclosure provide context without inventing real product actions.

Five human-authored paired fixtures make the feature testable without local inference. They are explicitly illustrative and pending, separate from AI output. Full source equality blocks source-ID collisions; the existing AI fingerprint filters stale suggestions. Optional AI presentation now returns fresh candidates to the preview section, allowing offline previews even when AI configuration is invalid. Tests exercise exact text/Unicode/tokens, all templates/themes, hostile markup, bounds, provenance, original/revised toggles, filters, stale AI and no-AI operation. Completion evidence is recorded in milestone_4_completion.md.

A user-facing guided test kit was also prepared with all source fields, exact project/context/manual-entry values, nine working cases, a validation-error file, a malformed input, and a walkthrough of implemented features. It avoids presenting later approval/export milestones as already implemented.

## Milestone 5 — decisions belong to a version
The user authorized editorial review and exports after the guided test showed that findings alone could not complete the correction workflow. The implementation separates original source records, initial AI analysis, retained editorial drafts and approved replacement mappings. Manual revisions let the workflow finish offline even if AI offers only findings or questions. Review processing lives in pure review.py and exporters.py; Streamlit forms and downloads live in ui/review_panel.py. No dependency or persistent database was added.

A source/context/full-guide fingerprint binds each decision to the evidence available during review. Adding unrelated records does not discard prior decisions; changed inputs make a draft stale, exclude its approval, and require explicit rebase plus review. Material text/rationale edits increment the revision version and reset approval and behavior confirmation; notes-only changes preserve the decision. Approval independently checks tokens, length, protected names and one-approved-version-per-source. The initial candidate and model identity remain available after human edits, avoiding attribution of human text to the model.

Reports recompute deterministic counts for the complete catalog, retain current matching AI processing outcomes, and separate proposed from approved text. JSON preserves exact source/extension metadata. CSV neutralizes formula-like cells; Markdown escapes HTML and link/image syntax so a report cannot turn imported content into remote-resource markup. Export is an explicit download, never a source rewrite. Initial AI tables remain analysis snapshots; editorial decisions are separately versioned.

The first new test batch passed 33 cases. A full regression exposed an old Milestone 4 expectation that a candidate should disappear after changing AI model settings. Milestone 5 intentionally retains a review draft with its original model provenance while hiding the stale analysis. The updated regression verifies that distinction and still withholds drafts after source changes. Additional tests cover partial AI reporting, stale AI snapshot rejection, forged/duplicate approvals, initial-candidate preservation and UI rejection/clarification plus blocked token approval.

Final measured checks: 266 tests passed in 8.45 seconds; Ruff lint/format passed (47 files); strict mypy passed on 20 source files; pip-audit found no known dependency vulnerabilities (unpublished local app skipped); localhost health returned OK. The local app remains running without a session-clearing restart. Editable installation initially failed with no-build-isolation because setuptools was absent; normal isolated build succeeded as 0.5.0. No fresh live model run was required for this editorial-only milestone. See milestone_5_completion.md and editorial_review.md. Milestone 6 remains outside this authorization.

## Milestone 6 — acceptance evidence and reproducible release
The release audit mapped every PRD acceptance criterion and found a real gap: source records could be added, but only candidate revisions could be edited. A pure validated source-edit function and separate UI form now preserve IDs/extensions, reject invalid edits atomically, keep files unchanged and make affected approvals stale. Approval checking also compares the retained source snapshot itself, not only its fingerprint. CSV exports retain source findings even without a revision, and formula-prefix tests cover additional control/Unicode whitespace.

An offline script uses existing core APIs to generate a separate fictional editorial session with nine sources, seven findings, four decisions and one approved replacement. Network-forbidden tests execute both the script and a UI review/preview/export session with zero connection/DNS attempts. A simulated real-adapter connection failure preserves manual approval/export. A published report schema validates both offline and live outputs. External package versions were snapshotted for reproducibility, without claiming a cross-platform/hash-locked release.

Browser QA used an isolated localhost server/session: five paired fixtures became pending illustrative drafts, one received explicit fictional behavior confirmation/approval, and the actual downloaded CSV was parsed to verify its source/text/status. Screenshots document the rendered comparison and summary. The temporary browser/server were closed without restarting the user's working instance. A final two-record installed-model run completed in 157.25 seconds: the button yielded one pending Submit Report candidate, while unknown Error 42 yielded three clarification questions and no revisions; no failed/partial records.

Adding the source editor broke an older positional button test; selecting the audit by label removed that fragility without relaxing assertions. Extending strict mypy to the demo script found one missing list annotation, which was fixed. The documentation directory unexpectedly disappeared during release work; the user confirmed it was unintended and requested restoration. Saved milestone copies and completion artifacts were restored and the current review/release changes reapplied. No executable source was lost, and no cause is asserted.

Final checks passed 283 tests in 10.66 seconds, Ruff lint/format (56 files), strict mypy (23 files), pip check and pip-audit with no known dependency vulnerabilities (unpublished local app skipped).
